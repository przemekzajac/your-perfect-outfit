# Atelier — build notes & decisions (read me first)

Built overnight while you slept. Here's what exists, how to run it, and every
decision I made on your behalf. Nothing here is locked — tell me to change any of it.

## What to open

- **`wardrobe/atelier/atelier_app.html`** — the combined app (needs the
  `demo/images/` folder beside it). Top nav: **Digital Wardrobe | Atelier**.
- A single-file **`atelier_app_standalone.html`** is generated on demand
  (`WARDROBE_EMBED=1 python3 build_app.py`) with all photos inlined — I'll send
  you that as the openable deliverable.

## The flow (what you'll see)

1. **Digital Wardrobe tab** — the women's demo closet as a moodboard (corner-icon
   cards, (i) details, remove → My bin, the returned-flag on 2 items). Same look &
   feel as the wardrobe you already approved.
2. **Atelier tab** — first visit runs the **14-question intake wizard** (guided
   cards, progress bar) → saves a **Style Profile** (localStorage, never asked
   again; editable via "Edit style profile" or Settings ▸ Reset).
3. **Outfit for today** — pick one of **6 moods** → it reads **today's weather**
   (browser geolocation → Open-Meteo, Warsaw fallback, optional city in Settings)
   → returns **3 complete outfits**, each a photo collage + an evocative name + a
   warm "why it works". "Show me three more" re-rolls.

## The stylist brain

- **`atelier.system.md`** — your Atelier prompt, stored verbatim, plus a strict
  JSON output contract for the bridge.
- **Two engines, one adapter:**
  - **Offline "sample stylist"** (built in, free, no setup) — a heuristic that
    respects mood, weather, formality, season, your no-gos (flats-only, no-bright,
    covered), and builds 3 distinct complete looks. This is what runs by default so
    the app always works.
  - **Live Atelier on Max** — the local bridge (below). When connected, "today's
    outfit" is generated by **Opus on your Max plan**.

## Running the real (Max) engine — `wardrobe/atelier/bridge/`

```bash
cd wardrobe/atelier/bridge
npm install
claude login            # authenticate with your Max account
unset ANTHROPIC_API_KEY  # IMPORTANT — otherwise it bills the API, not Max
npm start               # -> http://localhost:8787
```
Then in the app: **⚙ Settings ▸ Local Atelier bridge URL → `http://localhost:8787`**.
It pings `/health` and shows "Connected — claude-opus-4-8 · Max". If the bridge
isn't running, the app silently uses the sample stylist.

## Decisions I made on your behalf

| # | Decision | Why |
|---|---|---|
| 1 | **Engine = Max + Opus, *text-only*** | The SDK research found Max (Agent SDK) can't send images to the model, and the image path needs a pay-per-token API key. Your prompt's Step-0 enrichment is text-based, so text-only is free on Max and well-aligned. The app still shows photos to *her*. |
| 2 | **Both tabs use the women's demo wardrobe** | So the whole product reads as one coherent women's app. Your original men's wardrobe build is untouched in the repo. |
| 3 | **Demo wardrobe = 30 curated items** (incl. 2 returned + 2 underwear) | Enough variety to build distinct outfits across all 6 moods/weather, and it proves the hard filters live. Polish names, to exercise the silent-translation logic. |
| 4 | **Weather = Open-Meteo + browser geolocation** | Free, no API key, CORS-friendly; Warsaw fallback + optional city field if location is denied. |
| 5 | **Offline sample stylist as default + Max bridge as upgrade** | I can't run your Max creds from my sandbox, so the app had to be demoable without it. Clean adapter → swapping engines is one setting. |
| 6 | **Hard rules enforced in code, not left to the model** | `returned_order:true` and `underwear` are filtered in both the app and the bridge; every returned `itemId` is validated against the wardrobe, so no hallucinated clothes. |
| 7 | **Kept the light/dark theme + a dark toggle** | Consistency with the wardrobe you approved. |
| 8 | **Re-roll + per-look refine buttons** (Bolder / Cozier / Swap shoes) | Matches the prompt's "push a look further" ending. |

## Honest caveats

- **I couldn't test the Max bridge end-to-end** (no Max creds / restricted network
  in my sandbox). It's written precisely to the SDK research; first run on your
  machine is the real test. If the SDK's `outputFormat`/`structured_output` shape
  differs in your installed version, it's a 2-line fix in `server.mjs` (there's
  already a text-JSON fallback).
- **Demo photos are representative** (sourced from the web like the Nike images),
  not a real person's clothes. Some fashion sites block scraping, so a few items
  may show a placeholder icon — see the build output for coverage.
- **Max + vision** isn't possible today (see decision #1). For the future SaaS,
  the engine adapter swaps to the API for true vision.
